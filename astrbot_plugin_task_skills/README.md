# 自动化skills学习

只修改插件，不修改 AstrBot 核心。将当前轮工具任务的可观察经验保存为可检索、可编辑、可回滚的结构化技能，并可发布到原生 SkillManager 扫描的库。生成内容始终是不可信参考，不是已验证成功的证明，也不是模型权重训练。

## 启动与管理页面

先登录现有 AstrBot dashboard，在左侧「插件 WebUI」分组打开 **自动化skills学习**。本插件与 `astrbot_plugin_screen_companion` 使用相同的插件拓展页面机制：核心自动发现 `pages/技能管理/index.html`，侧栏使用 `metadata.yaml` 的 `display_name: 自动化skills学习`，无需修改核心或注入菜单。也可在同一 dashboard 地址访问：

```text
<dashboard 地址>/plugin-page/astrbot_plugin_task_skills/技能管理
```

旧版直链入口继续保留，在**同一浏览器、同一地址**访问：

```text
<dashboard 地址>/api/plug/task-skills
```

例如 dashboard 地址确实为 `http://127.0.0.1:6185` 时，页面是 `http://127.0.0.1:6185/api/plug/task-skills`。没有读取当前端口配置，不保证此示例端口就是你的端口。管理员指令 `/技能管理` 返回不含令牌的访问路径，可以在群中使用而不泄露凭据。

插件不启动独立 HTTP 服务，也不新增监听端口。AstrBot 加载插件后，先登录现有 AstrBot dashboard，再在同一浏览器、同一地址打开管理页面。页面由 dashboard 提供认证，插件不需要单独启动命令，也不要为了本插件重启服务。

页面支持搜索名称/标签/适用条件/工具、查看、完整 JSON 编辑、删除、发布、选择历史版本回滚、技能/版本统计，以及 schema 中全部七项配置：自动学习、Provider ID、技能容量、冷却秒数、全局共享、审核模式、审核通过后自动发布。Provider ID 只接受手动输入，不返回 Provider 配置或 API Key。响应式布局，所有插件 HTML/CSS/JS 在 `pages/技能管理/index.html`，无 CDN、外部字体或网络资源。拓展页使用核心注入的官方 `AstrBotPluginPage` Bridge，不从 iframe 直接请求 API 或读取登录令牌。编辑不支持重命名；推荐通过页面编辑，避免聊天平台拆分 JSON。

本版本存在可用的认证插件路由，因此**不启动独立 HTTP 服务，不新增监听端口**。页面继承 dashboard 的网络暴露范围；建议 dashboard 只在本机或受信网络访问。本插件不更改 dashboard 绑定地址，不新增公网开放。未登录不能访问；写操作额外要求同源 Origin、JSON 和每个登录用户名独立的随机 CSRF 值。CSRF 保存在内存，1 小时过期，刷新页面重新获取；不会生成含凭据的页面链接。旧直链调用 `/api/plug/task-skills/api`，CSRF 放请求头；官方 Bridge 调用 `/api/v1/plugins/extensions/astrbot_plugin_task_skills/api`，CSRF 放 JSON。v1 路由额外调用核心 `require_dashboard_user` 并核对登录身份，拒绝仅持有通用 API Key 的访问；资源 asset-token 不能用于管理 API。dashboard 登录账号属于管理身份，普通聊天用户不能调用管理指令。

入口依赖当前安装的 dashboard 已有插件 Pages 与侧栏支持。代码落盘不会使运行中的插件自动加载新版；管理员可自行决定使用 dashboard 插件重载并刷新页面，本次不重启 Bot、不替换前端构建产物。如果正在运行的 dashboard 前端构建没有该侧栏机制，仅插件修改不能补齐侧栏，应使用插件拓展页入口或旧直链，不保证未验证的运行界面已经出现菜单。

隔离模式下，dashboard 没有聊天发送者身份，页面**不列出共享库或任意隔离库**，禁用技能操作，仅显示状态并允许管理员重新开启共享。隔离用户读取、管理员管理请使用聊天指令。不会为了 UI 把不同用户的数据聚合。

## 页面分层与技能分类

管理页分为“技能库”“审核工作台”“插件设置”。技能库使用列表与详情两栏，手机屏幕堆叠；审核工作台进入时优先筛选待审核候选，仍可切换全部、已批准或已拒绝。插件设置独立显示，不挤占主列表。详情中“审核与发布”单独分组，备注非必填，原有 JSON 编辑、批准、批准并发布、拒绝、发布、删除和历史回滚操作保留。

“技能分类”直接基于当前 `skill.tags` 标签生成，一个技能可同时属于多个分类；无标签的旧版五字段技能归“未分类”，不会新增必填 `category` 或迁移数据。分类下拉显示全库各标签技能数，每个技能在同一标签只计一次；多标签分类数不能相加作为技能总数。顶部显示全库状态、分类和未分类统计，列表显示当前筛选结果数。关键词搜索、审核状态与分类筛选取交集；“重置筛选”清空三项。筛选隐藏某个技能不会清除详情选择或审核备注；数据刷新按名称保持选择，新 revision 才重置备注。

修改分类时选择技能，点击“编辑 JSON”，修改 `tags` 字符串数组后点击“保存新版本”。增强结构必须同时保留 `tags`、`conditions`、`tools`、`workflow`，各列表 1-8 项，标签每项 2-100 字符，并遵守既有敏感内容校验。旧版可保持未分类；若要手工分类，需在完整 JSON 中补齐上述四项真实内容，不能只新增 `tags`。保存通过原有 `edit` API 提交完整技能与当前 revision，版本冲突需刷新核对；修改分类也会生成待审核新版本，即使自动审核模式下也不能绕过管理员审核。已批准旧版快照保持可用。

此次只改页面、文档与离线测试，后端、schema、真实技能数据和原生文件未修改。已有插件已加载时，浏览器重新加载管理页即可读取新 HTML，旧直链也在每次请求读取页面文件；“刷新数据”只刷新技能数据，不更新已加载的页面代码。若浏览器仍显示旧版，可强制刷新或关闭后重新打开页面，不需为此次纯页面修改重启 Bot。

## 指令与示例

普通用户可读取当前作用域。尖括号内容替换为实际值：

- `/技能列表`
- `/技能查看 <名称>`
- `/技能搜索 <关键词>`
- `/技能统计`
- 模型工具 `search_task_skills(query)`：当前作用域最多返回 3 个相关技能。

示例：

```text
/技能列表
/技能查看 verify-document
/技能搜索 文档校验
/技能统计
```

以下操作必须通过 `event.is_admin()`，即 AstrBot 的管理员身份，不是群主身份猜测：

- `/技能管理`：显示 dashboard 页面路径，不含任何 token。
- `/技能删除 <名称>`：删除插件技能及完整版本历史；共享模式下先撤回未人工修改的原生发布文件。
- `/技能编辑 <名称> <完整JSON>`：保存新版本；支持旧结构，但新增学习要求增强结构。
- `/技能回滚 <名称> <revision整数>`：恢复历史内容作为一个新版本，保留原历史。
- `/技能发布 <名称>`：仅共享模式，发布至原生库。
- `/技能审核 <名称> 批准|批准发布|拒绝 [可选备注]`：备注非必填，可直接批准或批准发布，无需填写测试说明。批准不代表已实际测试，不自动补写验证结论。
- `/技能学习开关`：修改当前作用域学习状态，共享模式下即全局开关。
- `/技能共享开关`：持久化全局共享状态；关闭前撤回插件原生发布文件。

示例：

```text
/技能管理
/技能删除 verify-document
/技能编辑 verify-document {"name":"verify-document","description":"用于核对授权文档格式。","steps":["使用授权文档工具检查文档。"],"checks":["核对工具返回结果，而不是只看最终总结。"],"cautions":["不要泄露私有文档内容。"]}
/技能回滚 verify-document 1
/技能发布 verify-document
/技能审核 verify-document 批准
/技能审核 verify-document 批准发布
/技能学习开关
/技能共享开关
```

`/技能编辑` 的 JSON 必须是一整段，`name` 必须与命令中的名称相同，不能重命名。增强结构的可选扩展字段是 `tags`、`conditions`、`tools`、`workflow`；启用增强结构时四个字段必须一起提供。模型工具示例：`search_task_skills("授权文档格式")`。返回内容中的 JSON 键名和 API 名称保持英文，以便程序稳定调用；页面会用中文解释每个字段。

页面“批准”和“批准并发布”直接执行，无弹窗，也不要求先输入备注。API 的 `verification` 字段保留，省略或空字符串均可批准，短备注也可使用；空备注保存为空字符串。非空备注仍检查文本类型、4000 字符上限与敏感内容，并脱敏 URL、邮箱、路径及长标识；识别到凭据则拒绝批准，错误响应不回显备注。聊天备注含空格时需按平台命令规则作为一个参数传入。管理员身份、dashboard 登录、Origin/CSRF、页面 revision 并发保护、共享发布限制与原生文件所有权保护均保持不变。

## 开关、学习与费用

- `shared_skills` 默认仍为 **true**；`auto_learn` 默认 true；`review_mode` 默认 `manual`（人工审核）。`auto`（自动发布）只对最终验证成功且通过校验的共享候选自动批准并发布，仍执行安全过滤和权限/原生文件保护，但存在误发布风险。
- `auto_publish` 保留为“管理员审核通过后自动发布”旧项。显式 `review_mode` 优先；缺省时按 `manual` 处理，旧 `auto_publish=true` 不会意外跳过审核。
- 页面保存设置时严格提交完整 schema 字段并调用真实 `AstrBotConfig.save_config` 持久化，单次保存失败或校验失败不会应用 partial update。容量范围为 1-1000，冷却范围为 60-86400 秒，Provider ID 最多 256 字符。
- 管理指令/UI 的共享开关保存在插件共享作用域 `state.json`，优先于 dashboard 插件配置默认值。已有隔离数据不搬到共享区，已有共享数据也不复制给隔离用户。
- 页面显示 `auto_learn` 的当前有效值、全局默认值和共享 scope override；保存会同步更新插件配置默认值及当前共享 scope override。隔离模式仍不通过 dashboard 聚合或修改隔离用户状态。
- 配置保存不会主动重启 Bot；当前实例立即更新容量、冷却、共享和审核模式行为，Provider ID 对新学习任务生效。正在执行或已预约的学习任务继续遵守既有关闭、忙碌和生命周期检查；插件重载后仍从持久化配置恢复。
- 每次满足门槛的学习尝试最多 **一次额外模型调用**，包括返回 null、校验失败、去重或保存失败时仍可能收费。合并、搜索、发布、UI 和管理操作不调用模型。不增加 embedding/重排依赖。
- 单个后台任务，无排队；繁忙时跳过。作用域冷却默认 600 秒（60-86400），全局容量默认 100（1-1000）。容量满时不再发起学习，即使可能合并，也优先避免额外费用。
- Provider 选择和生成共用 60 秒 timeout；卸载取消并等待任务、关闭 UI 会话、移除自己注册的路由。取消能否中断远端计费取决于 Provider。
- 只采集当前 agent 轮次 hook 返回的工具**公开 text**和最终公开总结；不读取工具输入参数、think/reasoning 字段、会话历史正文或凭据文件。runner 消息仅核对当前轮角色、公开总结与工具调用 ID/名称。
- 拒绝有错误、失败、未完成、异步后台、缺失结果或生命周期不匹配的任务。只用工具名不能生成新技能。提示词要求证据不足/未知步骤返回 `null`，绝不推断成功。
- 敏感字段、常见密钥格式命中即拒绝整段；URL、邮箱、路径、长标识脱敏。单段超过 4000 字符拒绝，工具结果最多 32 条缓存，每条最多 800 字，学习载荷最多选 16 条；公开总结最多 1000 字。不是通用 DLP：任意私人自然语言无法可靠自动识别，敏感任务应关闭自动学习。
- 强校验 exact schema、长度、列表数量、操作标识、工具名确实存在于本轮、敏感字符与资源。结构验证不等于事实证明，模型仍可能写出不正确步骤，发布前应人工复核。

## 增强结构、旧版兼容与合并

旧版五字段仍可读取、搜索、编辑，增强版增加四个必需字段：

```json
{
  "name": "verify-document",
  "description": "用于核对授权文档是否符合要求的格式。",
  "steps": ["使用已授权的文档工具检查文档。", "对照要求的格式检查返回结构。"],
  "checks": ["核对工具实际返回结果，而不是只看最终总结。"],
  "cautions": ["不要泄露私有文档内容。"],
  "tags": ["文档", "验证"],
  "conditions": ["已有授权可用的文档工具"],
  "tools": ["document_tool"],
  "workflow": ["inspect-document", "verify-document"]
}
```

生成前只在当前作用域检索本插件所有权、正文锚点和 metadata digest 校验通过、且没有陌生附加文件的技能。包含 pending 与 approved 当前候选，排除 rejected；按任务词匹配及真实工具交集排序，最多提供 3 条摘要。每条仅含名称、审核状态、用途描述（最多 300 字）、条件（最多 3 项）、标签（最多 4 项）、工具及流程（各最多 8 项，每项最多 100 字）；不发送完整正文、历史、原始证据或批准快照。摘要经过 `safe_task` 脱敏，没有额外模型调用或 embedding。pending 只作为去重参考，不进入执行检索；普通 `search_task_skills` 仍只返回已批准快照。候选摘要不是可信指令，也不是本轮成功证据。

严格正文去重忽略名称及 `success_evidence`（e1/e3 是不同任务的局部证据 ID），条件和标签按 NFKC、大小写、空白、句末标点规范化后集合比较，工具按原标识集合比较，正文步骤/检查/注意事项及流程仍严格比较。重复任务仅更新 bounded 本轮 evidence 和单独的 `evidence_refs`，不改 skill 正文、revision、历史、digest、审核状态或批准快照，也不触发自动批准/发布。旧 skill 中的证据 ID 随旧正文保留；本次 evidence 的引用以 `evidence_refs` 为准，不跨任务拼接局部 ID。存储完整性 digest 仍使用旧算法，不迁移已有记录。

保守合并要求**规范化后的用途 description 一致、适用条件集合一致、至少两个标签一致、至少两个不同流程操作且操作集合及末步一致、工具集合相等或一方为另一方子集、只有一个匹配候选**。仅 `find-`、`read-`、`inspect-`、`list-` 观察操作允许顺序细差异，其他操作的相对顺序不变；不做同义词猜测，不删除否定词，不把不同工具 namespace 当同一工具。共同找文件/读文件不代表同一目的，图片数量统计、查找压缩文件并发送、检查插件结构不能据此合并。用途表述不同或条件有歧义时宁可保留分立候选。旧版无增强结构不会自动合并。保留原名称，采用本轮证据提炼步骤，合并检查/注意事项/标签；列表溢出拒绝合并。

同一次生成可选返回 `existing_skill_name` 或 `merge_target`（两者不能同时出现）；字段在校验前取出，不写入 skill schema。代码要求引用确在生成前提供的当前作用域候选中、revision 未变，并重新验证上述用途/条件/流程/工具条件。任意名称、原生 `task-learned-` namespace、跨作用域或用途不符引用拒绝本次保存。模型引用不能绕过检查，也不能在多个同用途匹配中任意选择覆盖；实际合并仍要求唯一匹配。模型生成的描述/流程不是独立事实证明，人工审核仍需核对真实任务和适用性。

此机制不自动扫描合并、删除或重写旧技能。本次没有读取或修改现有 5 条原生技能数据；`inspect-plugin-skill-store` 与 `inspect-pending-skill-candidates` 只有实际用途和适用条件验证一致后才适合提出合并建议，不能仅凭名称或共同检查文件子流程合并，本次不作合并建议或执行合并。

新生成技能默认使用简体中文：`description`、`steps`、`checks`、`cautions`、`conditions`、`tags` 的内容使用中文；JSON 字段名、工具原名 `tools`、英文 kebab-case 的 `name` 和 `workflow` 保持英文。学习任务不限领域，不只针对开发。`SKILL.md` 的动态章节、信任提醒及管理页详情章节使用中文。

旧版五字段技能（`name`、`description`、`steps`、`checks`、`cautions`）继续支持读取、搜索、编辑和回滚，不要求立即迁移。旧记录的 `owner` 标识 `astrbot_plugin_task_skills/v1` 保持不变；首次编辑或合并时才惰性升级为 storage version 2，原内容进入 revision 1。无 `anchor_hash` 的旧 v1 英文 Markdown 用保留的旧模板校验所有权；有锚点的记录仍校验原哈希。读取不改写已有 Markdown、metadata 或 digest，中文章节不会使旧锚点失效。

旧英语技能正文不会自动翻译，也不会额外调用付费模型翻译已有内容。用户可在审核时通过 JSON 编辑自行改为中文，再验证、批准和显式发布。动态展示只改变章节与提醒，不翻译既有字段值；已发布原生文件不会自动重写，人工内容与被人工修改的发布文件仍受所有权保护。

每次合并/编辑/回滚保留完整历史。最多 20 个历史版本，满后拒绝继续编辑而不是悄悄丢历史。UI 编辑用 revision 乐观并发校验。检索额外加权标签、工具名、适用条件，无外部依赖。

## 存储与发布原生库

- 插件数据仍位于 `StarTools.get_data_dir("astrbot_plugin_task_skills")` 下；不读取现有持久数据来测试。作用域是会话+发送者哈希或固定共享哈希。
- v1 owner 标识保留，旧记录按旧格式验证，首次编辑/合并时惰性升级为 version 2，旧内容进入 revision 1。无需破坏性迁移。
- 新技能通过临时目录 rename 发布；更新将当前 skill、摘要和全部历史原子写入 `index.json`。旧 `SKILL.md` 保留作为所有权锚点；**更新后的当前内容以 index.json 为准**，查看、检索和原生导出均动态渲染当前版本，不直接读取旧 Markdown 作为最新内容。
- 拒绝路径穿越、直接 symlink、foreign owner、人工改动的 Markdown、摘要不匹配和陌生额外文件。人工修改 index JSON 不受密码学认证保护；这是同进程本地文件所有权检查，不是抵御本机恶意管理员的安全边界。
- 原生路径通过真实 `get_astrbot_skills_path()` 获取；写 `data/skills/task-learned-<名称>/SKILL.md`，frontmatter 使用带前缀名称；`.task-owner.json` 记录插件 owner 与内容摘要。不调用虚构 SkillManager API，也不改原生 `skills.json` 或人工文件。
- 已存在的 native 目录必须只有本插件两个文件且哈希匹配才能更新/撤回；否则拒绝。新条目目录原子 rename，更新先原子提交旧/新有效摘要再原子替换 Markdown，崩溃后可恢复。不会覆盖人工技能或被人工修改的发布文件。
- 仅固定共享作用域可发布。关闭共享撤回本插件完整原生条目；若某条已人工修改则**拒绝切换**，避免静默进入隔离却遗留全局资料。必须人工检查修改过的条目，不会擅自删除。直接 dashboard 配置关闭共享时，插件 initialize 也检查并撤回；失败会阻止初始化，需处理冲突再加载。
- `manual` 模式的新学习和相似合并更新保持待审核，不自动批准、检索或发布；已批准旧版本在候选待审期间保持可用。`auto` 模式只处理本次通过最终验证和内容校验的新候选或保守合并候选；重复候选不会触发批准。已有技能的手工编辑及回滚仍需管理员审核/发布。
- 原生 `SkillManager.list_skills` 每次扫描目录并默认启用新技能；agent 使用该 manager。sandbox 同步、原生显式禁用状态和实际使用仍由 AstrBot 控制，本插件未验证在线调用或沙箱同步。

发布只允许固定的全局共享作用域。页面或 `/技能发布 <名称>` 会把技能写入 AstrBot 原生技能目录，目录名为 `task-learned-<名称>`；插件只管理自己创建且哈希未被人工修改的 `SKILL.md` 和 `.task-owner.json`。不会修改原生 `skills.json`，不会覆盖人工技能。关闭共享、删除技能或撤回发布时，如果文件已被人工修改会拒绝操作，需要管理员先检查冲突。
